## 关键数据传递路径

### 从 101 到 108 的长线数据

```
101: import triton
  driver ───────────────────────→ 103: JITFunction.run() → get_current_device()
  backends ──────→ 102: make_backend() → 选择 backend
  JITFunction ───→ 102: JITFunction(fn) 实例化
  compile ───────→ 102: self.compile = compile → 104: self.compile(src, ...)
  ASTSource ─────→ 102: self.ASTSource = ASTSource → 104: ASTSource(self, ...)
  CompiledKernel → 102: self.CompiledKernel = ... → 105: return CompiledKernel(...)
  ir / passes / llvm ──────────→ 105~108: MLIR 操作全部依赖这些绑定
```

### create_binder() 是 102→103 的桥接

```
102: self.device_caches = defaultdict(create_binder)
      create_binder() 返回:
        kernel_cache={}, key_cache={}, target, backend, binder
                                  │
103: self.device_caches[device] → (kernel_cache, key_cache, target, backend, binder)
      binder(*args) → (bound_args, specialization, options)
      compute_cache_key(key_cache, ...) → key
      kernel_cache.get(key) / kernel_cache[key] = kernel
```

### compile() 是 103→108 的枢纽

```
103: kernel_cache 未命中 → _do_compile()
104: _do_compile() → src = ASTSource(self, ...) → self.compile(src, target, options)
105: compile()
      ├─ backend = make_backend(target)
      ├─ ir.load_dialects(context)          ← 使用 101 加载的 ir 模块
      ├─ src.make_ir() → module             ← Python AST → MLIR ModuleOp
      ├─ backend.add_stages(stages, ...)     ← 注册各 stage
      └─ for ext, compile_ir in stages:
           module = compile_ir(module, metadata)
106:     make_ttir(module, metadata, ...)    ← 使用 101 加载的 passes.common/ttir
          pm.run(module, 'make_ttir')
          return module
107:     make_ttgir(module, metadata, ...)   ← 使用 101 加载的 passes.ttgpuir/nvidia
          pm.run(module, 'make_ttgir')
          return module
108:     make_llir(module, metadata, ...)    ← 使用 101 加载的 passes.convert/llvm
          pm.run(module, 'make_llir')
          return str(module)                 ← LLVM IR 文本
      └─ return CompiledKernel(src, metadata_group, hash)
```

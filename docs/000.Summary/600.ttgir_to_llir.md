# TTGIR → LLIR 转换

> 从 TTGIR（TritonGPU dialect）到 LLVM IR / NVVM dialect 的 lowering 过程分析

---

## 一、转换概述

```
TTGIR (ttg dialect, 含 #blocked layout 编码)
    │
    │  make_llir() 管道:
    │  allocate_warp_groups → scf_to_cf → allocate_shared_memory
    │  → to_llvmir (主 lowering) → canonicalizer → cse
    │
    ▼
LLIR (LLVM Dialect, llvm.* ops + nvvm.* ops)
```

**核心变化**：所有 `tt.*`, `ttg.*`, `arith.*`, `scf.*`, `math.*` 等 MLIR dialect 操作被降级为 `llvm.*` 和 `nvvm.*` 操作。GPU layout 编码 `#ttg.blocked<...>` 被展开为具体的线程索引计算。

### 3.3 TTGIR 新增操作（pipeline 后）的 lowering

完整 pipeline 在 TTGIR 阶段引入的操作及其 LLIR 降级：

| TTGIR | LLIR | 说明 |
|-------|------|------|
| `ttg.local_alloc %tensor → memdesc` | `llvm.alloca` / shared memory 分配 | 在 shared memory 中分配 buffer |
| `ttg.local_load %memdesc → tensor` | `llvm.nvvm.ldmatrix...` (matmul) | 从 shared memory 加载到寄存器 |
| `ttg.convert_layout %t : <A> → <B>` | 展开为寄存器重排 / 共享内存读写 | layout 转换降级 |

| `#ttg.swizzled_shared<...>` | `ldmatrix` 自动处理 swizzle 模式 | 共享内存 bank conflict 避免 |

## 四、layout 编码的展开

`#ttg.blocked` 编码在 LLIR 阶段被展开为具体的 GPU 线程索引计算。以 `vec_add` 的 `#blocked = #ttg.blocked<{sizePerThread=[1], threadsPerWarp=[32], warpsPerCTA=[4], order=[0]}>` 为例：

```
TTGIR: `tt.make_range {end=128, start=0} : tensor<128xi32, #blocked>`

LLIR 展开为:
  %tid = nvvm.read.ptx.sreg.tid.x : i32          ← 线程 ID (0..127)
  %laneid = llvm.and %tid, 31 : i32                ← warp 内线程号 (0..31)
  %warpid = llvm.udiv %tid, 32 : i32               ← warp 号 (0..3)
  %elem_idx = llvm.add %warp*32, %laneid : i32     ← 元素索引

对应关系:
  线程 0..31   (Warp 0)   → 元素 0..31
  线程 32..63  (Warp 1)   → 元素 32..63
  线程 64..95  (Warp 2)   → 元素 64..95
  线程 96..127 (Warp 3)   → 元素 96..127
```

PTX load/store 指令中的具体线程索引计算包含更复杂的位操作（`llvm.shl`, `llvm.or`, `llvm.xor` 等），这些是 LLVM 对 `make_range` 和 swizzle 模式优化后的结果。

## 五、完整 lowering 链示例（vec_add）

```
Python: z = x + y
  ↓
TTIR:  %z = arith.addf %x, %y : tensor<128xf32>
  ↓ (TTGIR: 添加 #blocked layout)
TTGIR: %z = arith.addf %x, %y : tensor<128xf32, #blocked>
  ↓ (convert-to-ttgpuir: layout 自动传播)
TTGIR: %z = arith.addf %x_5, %y_7 : tensor<128xf32, #blocked>
  ↓ (make_llir: to_llvmir pass)
LLIR:  %c = llvm.fadd %a_20, %b_23 : f32
         ↑ 每个线程只处理 1 个 f32 元素 (sizePerThread=1)
  ↓ (LLVM O3 optimize)
PTX:   add.f32 %f3, %f1, %f2;
```

**关键变化**：`tensor<128xf32>` 在 TTGIR 中是 128 个 f32 的抽象张量；在 LLIR 中变为每个线程持有 1 个标量 f32（`sizePerThread=[1]`），由 `#blocked` layout 编码控制线程到数据的映射。

`jit()` → 返回 `JITFunction` 实例：

```python
# triton/runtime/jit.py:751
class JITFunction(KernelInterface):
    def __init__(self, fn, ...):
        super().__init__(fn)
        self.params = []                                  # 解析函数参数
        for i, param in enumerate(self.signature.parameters.values()):
            self.params.append(KernelParam(i, param, ...))

        # 关键: 按 device 惰性创建 binder

        self.kernel = None
```

`create_binder()` 是惰性初始化的入口点：

```python
# triton/runtime/jit.py:658
def create_binder(self):
    target = driver.active.get_current_target()     # 检测 GPU 目标
    backend = make_backend(target)                  # 选择后端
```

**问题：** 此时只是注册了装饰器和缓存结构，真正的 target 检测和 backend 选择**延后到了首次调用时**。

### 4.2 `JITFunction.run()` — 编译/执行入口

```python
# triton/runtime/jit.py:695
def run(self, *args, grid, warmup, **kwargs):
    device = driver.active.get_current_device()          # 当前设备 ID
    stream = driver.active.get_current_stream(device)    # CUDA/HIP stream

    # 首次访问 → 触发 create_binder()
    kernel_cache, kernel_key_cache, target, backend, binder = self.device_caches[device]

    bound_args, specialization, options = binder(*args, **kwargs)  # 参数绑定
    key = compute_cache_key(kernel_key_cache, specialization, options)

    kernel = kernel_cache.get(key, None)
    if kernel is None:
        # 编译新内核
        kernel = self._do_compile(key, signature, device, constexprs, options, attrs, warmup)

    if not warmup:
        # 启动 GPU 内核
        kernel.run(grid_0, grid_1, grid_2, stream, kernel.function, ...)
    return kernel
```

### 4.3 `_do_compile()` — 转发到 compiler

```python
# triton/runtime/jit.py:826
def _do_compile(self, key, signature, device, constexprs, options, attrs, warmup):
    src = self.ASTSource(self, signature, constexprs, attrs)
    kernel = self.compile(src, target=target, options=options.__dict__)
    kernel_cache[key] = kernel
    return kernel
```

这里的 `self.compile` 实际就是 `triton.compiler.compile`（在 `create_binder()` 中赋值）。

**`ir.load_dialects()`** 注册到 `mlir::MLIRContext` 的 dialect 包括：

| **NVIDIA 专属** | TritonNvidiaGPUDialect, NVGPUDialect, NVWSDialect |
| **AMD 专属** | TritonAMDGPUDialect |

### 5.2 Python AST → TTIR (MLIR)

```python
module = src.make_ir(target, options, codegen_fns, module_map, context)
# → ASTSource.make_ir() → code_generator.py: ast_to_ttir()
```

**`ast_to_ttir()`** 流程：

```
Python AST (kernel 函数的语法树)
    ↓ CodeGenerator (ast.NodeVisitor) 访问节点
    ↓ 使用 ir.builder 调用 C++ MLIR OpBuilder
    ↓ 生成 tt dialect 操作: tt.func, tt.load, tt.store, tt.dot, ...
    ↓ 嵌套 scf.for, arith.addi, math 等操作
    ↓
mlir::ModuleOp (包含 tt + arith + scf + math dialect)
```

生成的 `module` 是完整的 TTIR，还未引入 GPU 数据排布信息。

```python
def add_stages(self, stages, options, language):
    capability = self._parse_arch(options.arch)
    if language == Language.TRITON:
        stages["ttir"]   = lambda src, meta: self.make_ttir(src, meta, options, capability)
        stages["ttgir"]  = lambda src, meta: self.make_ttgir(src, meta, options, capability)
    stages["llir"]  = lambda src, meta: self.make_llir(src, meta, options, capability)
    stages["ptx"]   = lambda src, meta: self.make_ptx(src, meta, options, ...)
```

## 六、Phase 4: 各 Stage 详解（以 NVIDIA 为例）

### 6.1 `make_ttir` — Triton IR 前端优化

```
输入:  tt dialect ModuleOp (含 arith, scf, math)
输出:  优化后的 tt dialect ModuleOp
Passes:
  inliner → rewrite_tensor_pointer → [rewrite_tensor_descriptor]
  → canonicalizer → combine → reorder_broadcast → cse
  → symbol_dce → loop_unroll
```

**关键作用：** 在与 GPU 无关的 TTIR 级别做化简和优化，为后续引入 GPU layout 做准备。

### 6.2 `make_ttgir` — TritonGPU IR 优化（核心）

```
输入:  tt dialect ModuleOp
输出:  ttg dialect ModuleOp (含 GPU layout 编码)
Passes:
  [转换] convert_to_ttgpuir → tt → ttg (引入 numWarps, layout 等)
  [通用] coalesce → f32_dot_tc → remove_layout_conversions
         → optimize_thread_locality → accelerate_matmul
         → prefetch → reduce_data_duplication → ...
  [NVIDIA] plan_cta → optimize_descriptor_encoding
  [SM80/90] fuse_nested_loops → hopper_warpspec → assign_latencies
            → schedule_loops → pipeline
  [SM100+] promote_lhs_to_tmem → warp_specialize → hoist_tmem_alloc
  [收尾] fence_insertion → lower_mma → sccp → cse → canonicalizer
```

**关键作用：** 引入 GPU 数据排布，针对具体架构做循环流水线、warp 特化、内存屏障插入等。

### 6.3 `make_llir` — TritonGPU → LLVM IR

```
输入:  ttg dialect ModuleOp
输出:  LLVM IR (MLIR LLVM Dialect)
Passes:
  allocate_warp_groups → scf_to_cf → allocate_shared_memory_nv
  → to_llvmir (TritonGPU → LLVM 主 lowering)
  → nvgpu_to_llvm → warp_specialize_to_llvm
  → nvvm_to_llvm → canonicalizer → cse → symbol_dce
  之后: llvm.optimize_module(O3)
```

**关键作用：** 将所有 TritonGPU 操作降为 LLVM IR，然后通过 LLVM 优化器做 O3 优化。

### 6.4 `make_ptx` / `make_cubin`

```python
def make_ptx(self, src, metadata, opt, capability):
    triple = 'nvptx64-nvidia-cuda'
    proc = sm_arch_from_capability(capability)
    features = get_features(opt, ...)
    ret = llvm.translate_to_asm(src, triple, proc, features, ...)
    return ret

def make_cubin(self, src, metadata, opt, capability):
    ptxas = get_ptxas(...).path
    # 调用外部 ptxas 编译器将 PTX 汇编为 cubin
    subprocess.run([ptxas, ..., f'--gpu-name={arch}', fsrc.name, '-o', fbin])
    return binaray
```

| **NVIDIA GPU** (SM70+) | `CUDABackend` | ttir → ttgir → llir → ptx → cubin | `.cubin` | MLIR → LLVM → PTXAS |
| **AMD GPU** (gfx90a+) | `HIPBackend` | ttir → ttgir → llir → amdgcn → hsaco | `.hsaco` | MLIR → LLVM → AMDGPU |
| **实验性: Gluon** | 同上 | (跳过 ttir) ttgir → llir → ... | 同上 | 更高级的融合管道 |

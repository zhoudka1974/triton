# TTIR → 优化后的 TTIR → TTGIR 转换

> 从 9 种代表性 Triton 内核的实际编译输出，展示从原始 TTIR 经过 TTIR 优化 passes、再到 `convert_to_ttgpuir` 进入 TTGIR 阶段的完整转换过程

---

## 一、四个阶段的 IR 对比

```
原始 TTIR (ast_to_ttir 输出)
    ↓  make_ttir() 管道
优化后的 TTIR
    ↓  convert_to_ttgpuir()  ← 核心转换
TTGIR (引入 GPU layout 编码)
    ↓  TTGIR passes (coalesce, accelerate-matmul, ...)
进一步优化的 TTGIR
```

---

## 二、各阶段的 IR 变化分析

### 阶段 0 → 阶段 1：TTIR 优化 passes 的效果

**执行管道**：`inliner → rewrite_tensor_pointer → canonicalizer → combine → reorder_broadcast → cse → symbol_dce → loop_unroll`

#### 溢出检查代码消除

```
阶段 0 (原始 TTIR):
  %c128 = arith.constant 128 : i32
  %pid_64 = arith.extsi %pid : i32 to i64        ← 溢出检查: 提升到 i64
  %c128_64 = arith.extsi %c128 : i32 to i64
  %off_64 = arith.muli %pid_64, %c128_64 : i64   ← i64 计算
  %max = arith.constant 2147483647 : i64
  %min = arith.constant -2147483648 : i64
  %le = arith.cmpi sle, %off_64, %max : i64       ← 范围检查
  %ge = arith.cmpi sge, %off_64, %min : i64
  %ok = arith.andi %le, %ge : i1
  %off_i32 = arith.muli %pid, %c128 : i32         ← 实际 i32 运算

阶段 1 (优化后):
  %c128_i32 = arith.constant 128 : i32
  %off = arith.muli %pid, %c128_i32 : i32          ← 直接 i32 运算
```

| 变化 | 说明 |
|------|------|
| `extsi`→`muli`→`cmpi`→`andi` 溢出检查链 | 被 `canonicalizer` pass 消除 |
| 两个 `arith.constant 128 : i32` | 被 `cse` pass 合并为一个 |

**指令减少统计**（以 vec_add 为例）：从 29 条减少到 13 条，**减少约 55%**。

---

### 阶段 1 → 阶段 2：`convert_to_ttgpuir` 的核心转换

**核心变化**：为每个 `tensor<T>` 类型附加 GPU layout 编码 `#ttg.blocked<...>`

#### 转换前（TTIR）

```mlir
%off_0 = tt.make_range {end = 128, start = 0} : tensor<128xi32>
%off_1 = tt.splat %off : i32 -> tensor<128xi32>
%off_2 = arith.addi %off_1, %off_0 : tensor<128xi32>
%x_5 = tt.load %x_4, %m_3 : tensor<128x!tt.ptr<f32>>
%z = arith.addf %x_5, %y_7 : tensor<128xf32>
```

#### 转换后（TTGIR）

```mlir
%off_0 = tt.make_range ... : tensor<128xi32, #blocked>
%off_1 = tt.splat %off : i32 -> tensor<128xi32, #blocked>
%off_2 = arith.addi %off_1, %off_0 : tensor<128xi32, #blocked>
%x_5 = tt.load %x_4, %m_3 : tensor<128x!tt.ptr<f32>, #blocked>
%z = arith.addf %x_5, %y_7 : tensor<128xf32, #blocked>
```

#### 统一变化

| 项目 | TTIR | TTGIR |
|------|------|-------|
| 标量运算 | `i32`, `f32` | 无变化 |
| 1D 张量 | `tensor<128xT>` | `tensor<128xT, #blocked>` |
| 2D 张量 | `tensor<32x16xT>` | `tensor<32x16xT, #blockedN>` |
| 指针张量 | `tensor<128x!tt.ptr<T>>` | `tensor<128x!tt.ptr<T>, #blocked>` |
| Module 属性 | 无 | `ttg.num-warps`, `ttg.target`, ... |

## 四、Layout 编码详解

### 1D blocked 编码（基本类型）

```mlir
#blocked = #ttg.blocked<{
  sizePerThread = [1],        // 每个线程处理 1 个元素
  threadsPerWarp = [32],       // 每 warp 32 个线程
  warpsPerCTA = [4],          // 每 CTA 4 个 warp
  order = [0]                 // 数据排列顺序（仅 1D，axis=0）
}>
```

线程到数据的映射（vec_add: `tensor<128xf32> → 4 warp × 32 threads × 1 element`）：

```
CTA 0:
  Warp 0: 线程 0..31 → 元素 0..31
  Warp 1: 线程 0..31 → 元素 32..63
  Warp 2: 线程 0..31 → 元素 64..95
  Warp 3: 线程 0..31 → 元素 96..127
```

### 2D blocked 编码（matmul 中的变体）

matmul 的 2D 张量会产生多种 blocked 变体：

```mlir
// 2D 布局: 32×16 数据 (32 个线程 × 1 线程/warp × 1 warp/CTA 在行方向)
#blocked = #ttg.blocked<{
  sizePerThread = [1, 2],      // 每线程 1 行 × 2 列
  threadsPerWarp = [32, 1],     // 行方向 32 线程，列方向 1 线程
  warpsPerCTA = [1, 2],        // 行方向 1 warp，列方向 2 warp
  order = [1, 0]               // 列优先排列
}>

// 另一种变体: 不同的 sizePerThread
#blocked5 = #ttg.blocked<{
  sizePerThread = [2, 1],      // 每线程 2 行 × 1 列
  threadsPerWarp = [16, 2],
  warpsPerCTA = [1, 1],
  order = [1, 0]
}>
```

### dot_op 编码（Tensor Core 操作数）

```mlir
#ttg.dot_op<{
  opIdx = 0,                   // dot 的第 0 个操作数（左矩阵）
  parent = #blocked6            // 继承自 #blocked6 的维度信息
}>
```

matmul 的 `tt.dot` 要求其输入操作数使用 Tensor Core 友好的 layout，`convert_to_ttgpuir` 自动为 dot op 的操作数分配 `#ttg.dot_op` 编码。

## 六、关键结论

### Module 级属性

```mlir
module attributes {
  "ttg.num-ctas" = 1 : i32,
  "ttg.num-warps" = 4 : i32,
  ttg.target = "cuda:89",
  "ttg.threads-per-warp" = 32 : i32
}
```

### Layout 编码类型（`#ttg.*` 类型别名）

| Layout 类型 | 用于 | 出现的内核 |
|------------|------|-----------|
| `#ttg.blocked<...>` | 通用数据排布 | 所有内核 |
| `#ttg.dot_op<...>` | dot 操作数（Tensor Core） | matmul |

### 未在此次测试中出现、但可能存在的 Layout 类型

```mlir
// NVIDIA Tensor Core MMA layout (SM80+)
#mma = #ttg.nvidia_mma<{...}>

// Shared memory layout
#shared = #ttg.shared<{...}>

// Swizzled shared memory (避免 bank conflict)
#swizzled = #ttg.swizzled_shared<{...}>

// 不同 layout 之间的转换
%converted = ttg.convert_layout %tensor
    : tensor<128xf32, #blocked> -> tensor<128xf32, #shared>
```

## 六、关键结论

| 结论 | 说明 |
|------|------|
| **TTIR 优化消除溢出检查** | `canonicalizer` + `cse` 消除了约 55% 的指令，主要为溢出安全代码 |
| **`convert_to_ttgpuir` 引入 layout** | 所有 `tensor<T>` → `tensor<T, #layout>`，是类型层面的改变 |
| **layout 自动传播** | `#blocked` 通过 SSA 数据流自动传播到所有张量操作数，包括控制流 |
| **dot 操作数自动用 dot_op** | `tt.dot` 的输入自动切换为 `#ttg.dot_op` layout |
| **标量不附加 layout** | `i32`, `f32`, 指针 `!tt.ptr<T>` 等标量类型无变化 |
| **不同维度产生不同 layout 变体** | 2D 张量的每个使用上下文会产生不同的 `#blockedN` 变体 |

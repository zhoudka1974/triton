# CPU↔GPU 数据传输机制

> 分析从 CPU 张量到 GPU、以及从 GPU 回读结果的完整数据流
> 覆盖 Triton 层、PyTorch 层、C/C++ 层

---

## 整体架构

```
Python 用户代码 (triton + torch)
    │
    ├─ Triton 层 ── 内核编译、参数提取、GPU 指针获取
    │
    ├─ PyTorch 层 ── Tensor 管理、CPU↔GPU memcpy
    │
    └─ C/C++ 层 ── CUDA Driver API / HIP Runtime API
         │
         ├─ NVIDIA: libcuda.so (driver) + libcudart.so (runtime)
         └─ AMD:    libamdhip64.so (HIP runtime)
```

---

## 核心结论

| 问题 | 答案 |
|------|------|
| **谁负责 CPU→GPU 拷贝？** | PyTorch（`tensor.to('cuda')` → `cudaMemcpyAsync` / `hipMemcpyAsync`） |
| **谁负责 GPU→CPU 拷贝？** | PyTorch（`tensor.cpu()` → `cudaMemcpyAsync` / `hipMemcpyAsync`） |
| **Triton 做拷贝吗？** | **不做**。Triton 只提取 `.data_ptr()` 获取 GPU 地址 |
| **数据生命周期** | 整个 Triton 内核执行期间数据在 GPU 显存中不动 |

---

## 一、Triton 层：参数提取与 GPU 指针获取

Triton **不执行任何 CPU↔GPU 数据拷贝**，它只做一件事：从 `torch.Tensor` 对象中提取 GPU 设备指针（`.data_ptr()`）。

### 1.1 内核调用入口

**软件包：Triton** | **文件：`python/triton/runtime/jit.py`**

#### `KernelInterface.__getitem__` — 第 364~370 行

```python
class KernelInterface(Generic[T]):
    def __getitem__(self, grid) -> T:
        return lambda *args, **kwargs: self.run(grid=grid, warmup=False, *args, **kwargs)
```

用户调用 `kernel[grid](x_tensor, y_tensor)` 时，`__getitem__` 返回一个 lambda，该 lambda 捕获 `grid` 并调用 `self.run()`，传入原始 Python 对象（`torch.Tensor`）。

#### `JITFunction.run` — 第 695~746 行

```python
def run(self, *args, grid, warmup, **kwargs):
    device = driver.active.get_current_device()
    stream = driver.active.get_current_stream(device)

    kernel_cache, kernel_key_cache, target, backend, binder = self.device_caches[device]
    bound_args, specialization, options = binder(*args, **kwargs)

    if not warmup:
        if callable(grid):
            grid = grid(bound_args)
        # bound_args.values() 是原始 torch.Tensor 对象，直接传给启动器
        kernel.run(grid_0, grid_1, grid_2, stream, kernel.function,
                   kernel.packed_metadata, launch_metadata,
                   knobs.runtime.launch_enter_hook, knobs.runtime.launch_exit_hook,
                   *bound_args.values())
```

**关键点**：`*bound_args.values()` 是原始 Python 对象（`torch.Tensor`），Triton 不做任何数据拷贝。

### 1.2 `CompiledKernel` — 启动器创建

**软件包：Triton** | **文件：`python/triton/compiler/compiler.py`**

#### `CompiledKernel._init_handles` — 第 436~463 行

```python
def _init_handles(self):
```

### 1.3 `getPointer()` — 提取 GPU 指针（核心）

#### NVIDIA 版本

**软件包：Triton** | **文件：`python/triton/backends/nvidia/driver.py`（动态生成 C 代码）第 388~429 行**

```c
static inline DevicePtrInfo getPointer(PyObject *obj, int idx) {
  DevicePtrInfo ptr_info;
  ptr_info.dev_ptr = 0;
  ptr_info.valid = true;

  // ★ 情况 1: Python int → 直接作为设备指针
  if (PyLong_Check(obj)) {
    ptr_info.dev_ptr = PyLong_AsLongLong(obj);
    return ptr_info;
  }
  // ★ 情况 2: 有 .data_ptr() 方法 (torch.Tensor) → 获取 GPU 地址
  PyObject *data_ptr = PyObject_CallMethod(obj, "data_ptr", "");
  if (data_ptr) {
    ptr_info.dev_ptr = PyLong_AsLongLong(data_ptr);
    return ptr_info;
  }
  // 情况 3: 不匹配 → 报错
  ptr_info.valid = false;
  return ptr_info;
}
```

**这是 Triton 数据传输的核心**。对于 `torch.Tensor`，调用 Python C API `PyObject_CallMethod(obj, "data_ptr", "")` 获取 GPU 设备地址。**不进行任何 memcpy**。

#### AMD 版本

**软件包：Triton** | **文件：`python/triton/backends/amd/driver.py`（动态生成 C 代码）第 538~578 行**

```c
static inline DevicePtrInfo getPointer(PyObject *obj, int idx) {
  if (PyLong_Check(obj)) { ... }
  if (obj == Py_None) { return ptr_info; }

  PyObject *ret = PyObject_CallMethodNoArgs(obj, data_ptr_str);
  ptr_info.dev_ptr = (hipDeviceptr_t)PyLong_AsUnsignedLongLong(ret);

  // ★ AMD 独有的指针验证：检查是否真的是 GPU 设备指针
  status = hipSymbolTable.hipPointerGetAttribute(&dev_ptr,
             HIP_POINTER_ATTRIBUTE_DEVICE_POINTER, ptr_info.dev_ptr);
  if (status == hipErrorInvalidValue) {
    PyErr_Format(PyExc_ValueError,
        "Pointer argument (at %d) cannot be accessed from Triton (cpu tensor?)", idx);
    ptr_info.valid = false;
  }
  ptr_info.dev_ptr = (hipDeviceptr_t)dev_ptr;
  ...
}
```

**NVIDIA vs AMD 差异**：AMD 多了 `hipPointerGetAttribute` 验证，如果传入了 CPU tensor 会报错。

## 三、PyTorch 层：Tensor 管理与 `.to(device)`

**软件包：PyTorch**

### 3.1 Python 接口

```python
import torch

# CPU → GPU
t_gpu = torch.tensor([1, 2, 3], device='cuda')    # 直接创建在 GPU 上
t_gpu = t_cpu.to('cuda')                            # 显式拷贝到 GPU
t_gpu = t_cpu.cuda()                                 # 等价于 .to('cuda')

# GPU → CPU
t_cpu = t_gpu.to('cpu')                              # 拷贝回 CPU
t_cpu = t_gpu.cpu()                                   # 等价于 .to('cpu')
```

### 3.2 C++ 内部调用链

PyTorch 源码位置（`github.com/pytorch/pytorch`）：

```
aten/src/ATen/native/
├── TypeProperties.cpp        ← Tensor.to() 方法
├── TensorTransformations.cpp ← cpu() / cuda() 方法
├── cuda/
│   ├── Copy.cpp              ← CUDA memcpy 实现
│   └── ...
├── hip/
│   ├── Copy.cpp              ← HIP memcpy 实现 (AMD)
│   └── ...
```

调用链：

```
Tensor.cuda()
  → at::native::to()                      aten/src/ATen/native/TypeProperties.cpp
    → tensor.to(DeviceType::CUDA, index)
      → at::native::copy_()               ← 实际拷贝操作
        → launch_copy_kernel()             CUDA kernel 或 cudaMemcpyAsync
```

### 3.3 底层 CUDA/HIP API

| 操作 | NVIDIA CUDA API | AMD HIP API | 作用 |
|------|----------------|-------------|------|
| 分配 GPU 内存 | `cudaMalloc(&ptr, size)` | `hipMalloc(&ptr, size)` | 在显存中分配空间 |
| Host→Device 拷贝 | `cudaMemcpyAsync(..., H2D, ...)` | `hipMemcpyAsync(..., H2D, ...)` | CPU→GPU |
| Device→Host 拷贝 | `cudaMemcpyAsync(..., D2H, ...)` | `hipMemcpyAsync(..., D2H, ...)` | GPU→CPU |
| Device→Device 拷贝 | `cudaMemcpyAsync(..., D2D, ...)` | `hipMemcpyAsync(..., D2D, ...)` | GPU 内部 |

## 四、完整数据流（端到端）

### NVIDIA GPU

```
用户: x = torch.tensor([1,2,3], device='cuda')    ← PyTorch 内部调用 cudaMalloc
用户: kernel[grid](x)                              ← 原始 Tensor 对象传入
  ↓
JITFunction.run()                                   jit.py:707
  → bound_args = {"x_ptr": Tensor(device='cuda')}
  ↓
C launch() → getPointer(x_tensor)                  生成 C 代码
  → PyObject_CallMethod("data_ptr")                ★ 提取 GPU 地址 (.data_ptr())
  → 返回 GPU 指针 (0x7f...)
  ↓
cuLaunchKernel(function, ..., params=[GPU指针])    ★ 启动内核（GPU 指针传入）
  ↓
GPU 内核执行 (在显存中直接读写，无数据拷贝)
```

### AMD GPU

```
用户: x = torch.tensor([1,2,3], device='cuda')    ← PyTorch 内部调用 hipMalloc
  ↓
C launch() → getPointer(x_tensor)                  生成 C 代码
  → PyObject_CallMethod("data_ptr")
  → 额外: hipPointerGetAttribute 验证是 GPU 指针   ★ AMD 独有的验证
  ↓
hipModuleLaunchKernel(function, ..., params=[GPU指针])
  ↓
GPU 内核执行
```

## 五、数据生命周期时间线

```
t=1: 用户在 CPU 上创建数据 ─────────────────────────→ CPU 内存
t=2: x = x.to('cuda')      ─── cudaMemcpyAsync ────→ GPU 显存
t=3: kernel[grid](x)       ←── .data_ptr() 提取 ────→ GPU 指针传给内核
t=4: GPU 内核执行                                  → GPU 显存中读/写
t=5: result = kernel[grid]()                        → GPU 显存中结果
t=6: x = result.cpu()       ─── cudaMemcpyAsync ────→ CPU 内存

Triton 只在 t=3 参与（提取 GPU 指针）
PyTorch 在 t=2 和 t=6 参与（实际数据拷贝）
CUDA/HIP Runtime 在 t=2,4,6 参与（GPU 管理和执行）
```

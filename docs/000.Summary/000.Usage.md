## Triton 使用 MLIR 的方法总结

Triton 深度集成 MLIR 作为其编译基础设施，整个编译流程分为 **Python → MLIR → MLIR 优化 → LLVM/PTX 代码生成** 四个阶段。

### 1. Python AST → MLIR (前端)

用户编写的 `@triton.jit` 函数进入编译流程时：

- **入口**：[`triton/compiler/compiler.py`](/home/zhoudka/work/code/triton/python/triton/compiler/compiler.py) 的 `compile()` 函数
- **AST 遍历**：[`code_generator.py`](/home/zhoudka/work/code/triton/python/triton/compiler/code_generator.py) 的 `ast_to_ttir()` 将 Python AST 转换为 MLIR。它通过 `ast.NodeVisitor` 遍历语法树，使用 `ir.builder`（MLIR C++ `OpBuilder` 的 Python 绑定）生成 MLIR 操作。
- **输出**：一个包含 **Triton Dialect** (`tt`) 操作的 `mlir::ModuleOp`

### 2. Triton 自定义的 MLIR Dialect

Triton 定义了四个核心 MLIR dialect，均通过 TableGen (`.td`) 文件定义：

| Dialect | 前缀 | 说明 |
|---------|------|------|
| **Triton** (`tt`) | `tt.` | 核心算子：`tt.dot`, `tt.load`, `tt.store`, `tt.reduce`, `tt.broadcast`, `tt.addptr` 等，还有 `tt.func` 定义内核函数 |
| **TritonGPU** (`ttg`) | `ttg.` | GPU 特定优化：`ttg.convert_layout`, `ttg.local_alloc/load/store`, `ttg.async_copy_global_to_local`。定义了多种数据排布编码：`BlockedEncodingAttr`, `DotOperandEncodingAttr`, `MmaEncodingTrait`, `SharedEncodingAttr` 等 |
| **TritonNvidiaGPU** (`ttng`) | `ttng.` | NVIDIA 专属：`ttng.warp_group_dot`, TMA 相关操作 (`ttng.tensor_descriptor_*`), 集群同步操作 |
| **Gluon** | - | 实验性 dialect，用于更高层次的内核融合 |

此外还使用了 MLIR 标准 dialect：`arith`, `math`, `scf`, `cf`, `ub` 等。

### 3. MLIR Pass Pipeline (优化流程)

编译管道以字符串形式定义在 `compiler.py` 中，主要分以下阶段：

#### (a) TTIR 优化阶段
- `ttir-combine` — 融合 `dot` 与偏置、简化 `addptr` 链
- `ttir-reorder-broadcast` — 将 broadcast 移到 elementwise 操作之后
- `ttir-rewrite-tensor-pointer` — 将 tensor pointer 操作转为传统 load/store
- `inline`, `canonicalize`, `cse` — MLIR 标准优化
- `scf-loop-unroll` — 循环展开

#### (b) TTIR → TTGIR 转换
- `convert-to-ttgpuir` — 将 `tt` dialect 转换为 `ttg` dialect，引入 GPU 数据排布信息

#### (c) TTGIR 优化阶段 (核心 GPU 优化)
- `ttgpuir-coalesce` — 合并访存，优化缓存友好性
- `ttgpuir-accelerate-matmul` — 为 Tensor Core 优化 dot 操作的输入/输出排布
- `ttgpuir-remove-layout-conversions` — 消除不必要的 `convert_layout` 操作
- `ttgpuir-pipeline` — 对循环应用软件流水线
- `ttgpuir-prefetch` — 从 shared memory 预取 dot 操作数
- `ttgpuir-schedule-loops` — 为流水线调度循环
- `ttgpuir-warp-specialize` — 线程束专业化
- `warp-specialize` (NVIDIA) — 更激进的线程束特化方案

#### (d) 后端转换 (Lowering)
- **NVIDIA**: `ttg` → `ttng` / NVVM → LLVM IR → PTX
- **AMD**: `ttg` → ROCDL → LLVM IR → GCN
- 使用 MLIR 标准转换：`scf-to-cf`, `cf-to-llvmir`, `arith-to-llvmir`, `index-to-llvmir`
- 最后通过 `nvvm-to-llvm` 或类似转换生成最终 LLVM IR

### 4. Pass 注册与调用机制

- **C++ 侧**：[`python/src/passes.cc`](/home/zhoudka/work/code/triton/python/src/passes.cc) 中的 `init_triton_passes()` 将 MLIR pass 暴露给 Python
- **Python 侧**：通过 `passes.common.add_inliner(pm)` 等模式使用，其中 `pm` 是 `ir.pass_manager`（对 `mlir::PassManager` 的封装）
- Pass 按命名空间组织：`passes.ttir`, `passes.ttgpuir`, `passes.convert`, `passes.llvmir`, `nvidia.passes.ttnvgpuir`, `amd.passes.ttgpuir`

### 总结

```
Python AST 
    ↓ ast_to_ttir()  [code_generator.py]
TTIR (tt dialect)
    ↓ TTIR passes (combine, reorder-broadcast, CSE, etc.)
Optimized TTIR
    ↓ convert-to-ttgpuir
TTGIR (ttg dialect)
    ↓ TTGIR passes (coalesce, accelerate-matmul, pipeline, warp-specialize, etc.)
Optimized TTGIR
    ↓ Lowering passes (scf→cf, cf→llvm, nvvm→llvm)
LLVM IR / NVVM
    ↓ LLVM optimization / PTXAS
PTX / 机器码
```
